Design tokens

The framework was built by combining design tokens and atomic design, creating a simple yet well-structured foundation. Design tokens act as the core of the system, centralizing visual decisions such as colors, typography, and spacing.

They were organized into two levels: primitive tokens (base values) and semantic tokens (applied usage in the interface). This structure makes maintenance easier, improves clarity, and allows global changes with minimal effort. Semantic tokens, which represent specific roles in the interface such as background color or error text, were defined separately from primitive tokens, which are raw values like #FFFFFF or 16px. This classification-based separation was applied in the framework’s token structure. They were integrated using Figma’s variables and styles to ensure consistent usage.

The token naming was designed to be intuitive, making it easier for both designers and developers to understand and use the system.


Components

In the initial phase, the focus was on building key components that could be used across different types of interfaces. This ensured a solid foundation, covering the most common use cases and allowing the system to be quickly applied in real projects.

Each component was designed to handle multiple variations within a single structure. Properties such as state (e.g., hover, disabled), size, and type were implemented using variants and boolean controls, allowing easy customization without duplicating components.


A key aspect of the construction was the direct connection between components and design tokens. All visual properties — such as colors, spacing, and typography — are driven by tokens, ensuring consistency and enabling global updates. This setup allows components to adapt quickly to different contexts while maintaining a cohesive visual system.


Each component was designed to cover different states, variations, and usage scenarios.


Supporting documentation has been added to describe the components, Each component includes descriptions and usage variations, making it easier for teams to understand and adopt the system. as well as clear and standardized terms for everyone.
